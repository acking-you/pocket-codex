# OpenCode 采用独立协议通路及附接托管

用户在设计文档交付后要求“按照你的建议”实施。首版使用独立 OpenCode 服务类型和 HTTP/SSE 会话控制器，附接并发布已有服务；Codex 保持现有协议和行为，基础传输、主题与缓存预算复用。将 OpenCode 映射成 Codex turn 或复用按端口查找并终止进程的托管生命周期，会错误扩大停止和授权语义，因此不采用。

代价是维护两套真实协议适配器；收益是兼容性与进程所有权清晰。首版不负责自动启动 OpenCode，也不获取供应商登录材料；任何后续 ManagedChild 扩展必须另行验证进程所有权。用户已确认按设计和任务清单施工，TDD 测试接口及当前验证状态见 [评估与任务清单](../opencode-construction-plan.md)。
